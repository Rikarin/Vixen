# tailwindcss variants that Vixen.Ui.Styling.Utilities does not resolve.
#
# 21 of tailwindcss@4.3.3's 88. Measured, not transcribed: Tools/Vixen.TailwindParity hands each
# variant's probe class to `Variants.TryResolve` — the same call the generator makes — and this file
# is what it refused. A variant v4 has that Vixen refuses and this file does not name fails as
# TWP008; a name here that Vixen has since learned fails as TWP009; a name here v4 does not have
# fails as TWP011. So the list can only shrink, and the day a feature lands the gate says which lines
# to delete.
#
# ⚠ This is doc 43's `expires-on` mechanism in the one form that cannot be walked past. A refusal
# written in a comment expires unobserved; a refusal written here stops the build the moment it stops
# being true, because deleting the line is what makes it green again.

# ── Pseudo-elements: A12, #233 ────────────────────────────────────────────────────────────────────
#
# `SelectorCompiler` refuses every `PseudoElementSelector` — "a pseudo-element generates a box of its
# own, and Vixen has no box without an element behind it" — and `Selector` carries no field saying
# WHICH one a rule names, which is the `[expires-on Vixen.Ui.Styling.Selector.PseudoElement]` anchor.
# Registering any of these ahead of the generated box would emit selectors the compiler refuses,
# which is F6's own failure mode.
#
# ⚠ `selection` is here for a DIFFERENT reason and is not behind the box. `TextField` paints the
# highlight from a `--selection-color` read off its own style, so `selection:bg-blue-200` would have
# to rewrite the utility's *property* — and `VariantEffect` is three strings that can only append to
# a selector, prepend to it, or wrap it in an at-rule. That one wants a fourth variant shape.
#
# ⚠ `placeholder` is NOT here, and that is the correction five audits of #233 needed: `TextField`
# builds the prompt as `Part("field-placeholder")`, a real child with its own tag, so it landed as a
# child combinator with no pseudo-element involved at all.
after
backdrop
before
details-content
file
first-letter
first-line
marker
selection

# ── Structural combinators ────────────────────────────────────────────────────────────────────────
#
# v4's `*:` is every direct child and `**:` every descendant. Vixen writes both through the arbitrary
# form — `[&>*]:` is the one variant family A15's audit found had end-to-end coverage — so what is
# missing is the shorthand and not the capability.
*
**

# ── States with no row in `Variants.States` ───────────────────────────────────────────────────────
#
# Each of these is one line in that table plus a computed-value scene, and each needs the state to
# exist in the engine first: `:visited` and `:target` are navigation concepts Vixen.Ui has no notion
# of, `:autofill` is a browser's form filler, `:default` is a form control's default submit button,
# and `inert` is an HTML attribute.
autofill
default
inert
target
visited

# ── Range and ancestor variants ───────────────────────────────────────────────────────────────────
#
# `max-sm:` and `min-sm:` are the breakpoint *ranges*; `TryResolve` reads `tokens.Screens` as a
# min-width and has no range syntax, which is the same gap #609 records for `@max-*` on containers.
# `in-*` is v4 4.1's "any ancestor matches", a `:where()` ancestor rather than the `.group` class
# `group-*` uses.
in
max
min

# ── At-rules the engine cannot evaluate ───────────────────────────────────────────────────────────
#
# `supports-[…]` and `starting:` wrap a rule in `@supports` and `@starting-style`. The cascade can
# carry an at-rule group — `Variants` already emits `@media` — but nothing evaluates either of these,
# and a group that always holds is worse than no group.
starting
supports
