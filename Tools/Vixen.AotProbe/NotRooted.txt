# Runtime assemblies Tools/Vixen.AotProbe does NOT root, and that `CheckAot` therefore asks nothing
# about. One assembly name per line; everything after the first space is why not yet.
#
# ⚠ This list can only SHRINK. `CheckAot` fails on a name that is here and has become rooted, and
# on a net10.0 non-test assembly under Core/ or Platform/ that is neither rooted nor here — so a new
# runtime assembly cannot join the uncovered set in silence, which is how this set reached
# sixty-six. The rule is build/AotRootingRule.cs and #506 is the expansion.
#
# ⚠ Being on this list is NOT "excluded from AOT". Many of these are in the probe's publish graph
# transitively, so ILC compiles whatever `Main` reaches inside them; what they do not get is the
# ROOTED question — is this assembly publishable ahead of time, rather than is one path through it
# clean — which is the only question the probe exists to ask (Tools/Vixen.AotProbe/README.md
# § Why it roots rather than calls).
#
# ⚠ Removing a line is real work rather than a list edit. `ILLinkTreatWarningsAsErrors` turns each
# newly rooted assembly into a fresh set of IL2xxx/IL3xxx findings and a build break until every one
# is fixed, and the only way to see them is an ILC publish — which is `nuke CheckAot` itself. Do a
# few at a time.
#
# Measured 2026-09-09: 29 of 95 rooted, 66 here. The `-ios`, `-android` and `-browser` heads and the
# netstandard2.1 generators are out of scope by target framework — `CheckAotIos` is the gate over
# the iOS one.
