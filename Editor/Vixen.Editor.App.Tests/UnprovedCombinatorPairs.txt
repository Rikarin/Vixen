# The declared `A > B` pairings no runtime sweep has proved, and why each one is unreached.
#
#     <parent> > <child>  <why no sweep reaches it, and where its producer is>
#
# Held against the residue of `CombinatorPairs.txt` minus every committed proof by
# `EditorCombinatorPairTests.Every_declared_pairing_is_proved_by_a_sweep_or_named_here`, EXACTLY and
# in both directions. This is the gate `Rikarin/Vixen#531` asks for: for every `A > B` a sheet
# declares, does an `A > B` occur anywhere at all?
#
# ⚠ NOT DERIVED and deliberately not regenerable. Every other census in this family is written back
# with VIXEN_REGENERATE=1; this one is not, because the reason column is the whole value of the file
# and a regeneration would fill it with a placeholder. A row is added by a person who chased the
# pairing and can say what builds it.
#
# ⚠ A row here is "unjudged", never "dead". Each names a producer that exists and a reason no sweep
# reaches it — an empty document, a dialog nobody opened, a menu built on demand. A pairing that
# turns out to have NO producer is not listed: it is a dead rule, and the answer is to correct or
# delete the rule, as `palette-row > text` was.
#
# ⚠ The list can only SHRINK. A row that becomes proved fails this test exactly as a new unproved
# pairing does — the same bargain `WhitespaceExempt.txt` and `RefusalExpiry.txt` make, and the reason
# is that an expiry list nobody prunes is a list that stops describing anything.
#
# What this gate is worth, said plainly: it catches the `compositor-editor > node-canvas` class of
# defect — a rule whose two halves are real tags that never meet — at the moment the rule is written,
# rather than when somebody notices a graph drawn at zero width. It does NOT catch a rule that is
# live somewhere and wrong under the scope it was written for; that is the scoped gate, which is
# still unbuilt (#531).
