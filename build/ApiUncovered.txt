# Projects that pack and whose public surface `CheckApi` does not read.
#
# CheckApi's coverage is a glob (build/Build.Api.cs), and a glob says nothing at all about what
# it does not match. An assembly outside it still produces a .nupkg, so every addition, every
# signature change and — the half that breaks a consumer without breaking anything here — every
# silent removal in it passes with nothing to approve it, while the target prints
# `Checking the public surface of N assemblies` and succeeds. That is the shape this repository
# keeps rediscovering: a gate reporting success on work it did not do.
#
# This file is the other half of the decision. The set the gate skips is written down, so that
# joining it is a reviewed line in a diff rather than silence, and ApiCoverageTests asserts the
# list and the tree agree in BOTH directions:
#
#   * a project in Vixen.slnx that packs, is not a test/generator/analyzer and has no
#     PublicAPI.Shipped.txt beside it, and no line here — fails,
#   * a line here naming a project that no longer exists, no longer packs, or now has a
#     baseline — fails, because a stale exemption is how a list like this stops meaning
#     anything.
#
# One line per project: its path from the repository root, whitespace, and the reason token.
#
# ⚠ Nothing here is an exemption somebody argued for on the merits. Twenty-one of the
# twenty-nine lines are #641, which is open and asks the opposite question: a package is a
# promise, so either these are covered the way Core/ is, or they should not be packing.
#
# Reason tokens:
#
#   editor-undecided   Editor/. The TOOLING profile in Directory.Build.props sets no IsPackable,
#                      so every Editor project takes the SDK default of *true*; only .App, .Host
#                      and .Testing opt out, and the two generators are excluded by the
#                      compiler-plugin profile. ⚠ "Editor/ is applications, so it does not pack"
#                      does not survive contact with the tree: all of these carry a
#                      <Description>, PackageTags and a PackageReadmeFile, which is a project
#                      that means to ship rather than an accident of the default.
#                      Vixen.Editor.Plugin is the one CheckApi names, and is not here. (#641)
#
#   library-undecided  A packable library outside Editor/ with a real referenced surface and no
#                      baseline — the same condition Vixen.Raven was in before it was covered.
#                      ⚠ This refutes the Coverage section of Tools/Vixen.ApiCheck/README.md,
#                      which says Tools/ "ships to nobody": seven Tools projects declare
#                      IsPackable=true, and two of them are libraries a consumer compiles
#                      against. (#749)
#
#   tool-command-line  Packed with PackAsTool. What a `dotnet tool install` promises is a
#                      command line and its arguments, not a type; the assembly is an
#                      implementation detail nothing references. A CLI-surface gate would be a
#                      different instrument from this one.
#
#   no-assembly        IncludeBuildOutput=false — the package is MSBuild logic or template
#                      content and carries no lib/, so there is literally no surface to read.
#                      This is the only token on the list that is a settled answer.
