# Flexbox fixtures in Taffy's corpus that Vixen does not yet get right.
#
# Every name here is a fixture that LAYS OUT and disagrees with Chrome. That is a different thing
# from the fixtures TaffyStyleMap refuses, which ask for a property this store has no field for and
# are skipped with a reason; those are not listed. It is also a different thing from a translation
# bug — thirteen of the original failures were this bridge conflating `start` with `flex-start`, and
# those were fixed rather than listed. Anything written down here is believed to be Vixen's.
#
# Names are given without the __{border,content}_box_{ltr,rtl} suffix, so one line covers up to four
# fixtures — and not always all four. align_baseline_multiline_column, align_baseline_multiline_column2
# and padding_border_overrides_size_flex_basis_0_growable each fail in their two border-box variants
# and pass in their two content-box ones, because box-sizing decides whether the bug is reachable.
#
# TaffyFlexConformanceTests asserts both that every failure is listed here AND that the totals are
# exactly the committed counts — so a line cannot quietly widen to cover a new failure, and fixing
# any one of these turns the suite red until the count and the line are both updated.

# ── CSS Flexbox §4.5, the automatic minimum size, when the content size comes from a DESCENDANT ──
#
# ⚠ This is the single biggest thing the corpus found, and the layout README predicted it almost
# exactly: it says Yoga's generator "emits no fixture that shrinks a measured leaf past its own
# content", and AutomaticMinimumSizeTests was hand-written to cover that. But it covers the *leaf*
# case — a node with a measure function. A flex item that is itself a container has a min-content
# size too, computed from what is inside it, and that floor is not applied. align_baseline_child_padding
# is the clearest: two 50px-wide siblings in a 90px content box, and Chrome shrinks one to 40 and
# the other not at all, because the second is floored at min(specified 50, content 60) = 50.
# Vixen shrinks both to 45.

# ── CSS Flexbox §9.7, resolving flexible lengths: min/max violations are frozen and redistributed ──
#
# `min_width` is two flex-grow:1 children in a 100px row, one with min-width:60. Chrome freezes the
# violating item at 60 and gives the whole remaining 40 to its sibling. Vixen raises the item's
# basis to 60 and then splits the leftover evenly — 80 and 20. The loop that re-runs distribution
# after clamping is what is missing, not the clamp.

taffy_issue_696_min_height
