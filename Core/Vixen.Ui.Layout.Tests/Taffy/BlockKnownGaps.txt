# Block fixtures in Taffy's corpus that Vixen does not yet get right.
#
# Same rules as KnownGaps.txt one file over, and the same reason for existing: a name here is a
# fixture that LAYS OUT and disagrees with Chrome, which is a different thing from the fixtures
# TaffyStyleMap refuses for a property this store has no field for. Names are given without the
# __{border,content}_box_{ltr,rtl} suffix, so one line covers up to four fixtures.
#
# TaffyBlockConformanceTests asserts both that every failure is listed here AND that the totals are
# exactly the committed counts, so a line cannot quietly widen and a fix cannot quietly land.
#
# 788 of the 884 block fixtures pass, plus ALL 28 blockflex. NONE fail and 96 are refused.
#
# ⚠ That was 764 + 24 with 124 refused, and the 28 that moved moved on the harness rather than on
# the algorithm: they wrote `scrollbar-width` on an `overflow: hidden` box, which reserves no gutter
# and could not have changed a single number, and TaffyStyleMap refused the whole fixture over it.
# Every one of the 28 went straight to green. Block is the corpus where that trade was free; flex
# and grid each paid for it with newly visible failures, which is the honest half of the story and
# is written up in their files.
#
# ⚠ THE SHAPE OF THIS FILE IS THE RESULT, AND THE RESULT IS NOW EMPTY. Every block and blockflex
# fixture that reaches arithmetic agrees with Chrome; what is left below the line is the refusal
# list, which is a scoping decision rather than a disagreement. Margin collapsing — the thing that
# makes this block rather than a stretch flex column, and about 180 of the 884 fixtures — is
# entirely green: sibling collapse, parent/first-child, parent/last-child, collapse-through, every
# one of the twelve things that blocks a collapse, and the sign rule where a positive and a negative
# margin add rather than maximise. So are auto margins in flow AND out of it, the intrinsic-width
# probe, RTL placement, relative insets, align-content over the stack, and percentage margins
# resolving against the inline size.
#
# ⚠ The one bucket that used to be here was never block formatting's: five
# `block_absolute_aspect_ratio_*` families in LayoutTree.Absolute.cs, which this file recorded as a
# pre-existing engine gap that block layout merely reached first. It said the fix belonged with the
# flex bucket of the same name rather than here, and it was right — all three corpora's copies of it
# closed together on agent/aspect-ratio, from one rule in LayoutTree.Absolute and the shared bounds
# merge in LayoutTree.Helpers.ResolveAspectBounds. Nothing was added to this file to pay for it.
#
# ⚠ THE COROLLARY IS THAT AN EMPTY LIST IS NOW THE ASSERTION. A block fixture that starts
# disagreeing with Chrome has nowhere to hide: TaffyBlockConformanceTests pins the failure count at
# ZERO, so the first regression names itself. Do not add a line here to make a build green.

# ── What is REFUSED rather than failing, and why each is honest ──
#
# ⚠ THIS SECTION WAS THE ONLY ONE OF ITS KIND IN THE PROJECT, AND IT WAS ALSO WRONG IN TWO PLACES.
# Block was the one corpus whose refusals were written down at all; flex and grid recorded a bare
# count and nothing else, and between the three of them 408 fixtures asserted nothing under a
# heading that said the corpora were nearly closed. The census now lives in UnsupportedFixtures.txt
# beside this file, covers all eight corpora, and is asserted rather than described. What follows is
# block's slice of it, kept here because a reader of this file should not have to open another one.
#
# 96 block fixtures never reach arithmetic. No blockflex fixture is refused any more.
#
#   64  scrollbar-width  — LayoutStyle has no scrollbar width, so a scroll container reserves no
#                          gutter. That is a real omission and it is doc 43 § F3's, not B1's.
#                          ⚠ Was 88. The other 24 were `overflow: hidden`, where there is no
#                          scrollbar to reserve a gutter for and the declaration is inert; the
#                          refusal was the harness's, not the store's, and they all pass.
#   16  text-align       — the legacy `-webkit-{left,right,center}` values, which align a block
#                          container's BLOCK-LEVEL children. Not the inline formatting context;
#                          this line used to say "inline alignment. Doc 43 § B3." and B3 landed
#                          without touching them, because they are a property of block layout.
#    8  display:flow-root — a block box that always establishes a formatting context. ⚠ This line
#                          used to add "`overflow: hidden` already gets the same behaviour out of
#                          this implementation today", which is true and is not a reason to alias
#                          the keyword: `block_flow_root_margin_non_collapse` is a flow root with
#                          `overflow: visible`, and mapping it to Block gets that one wrong. Four
#                          of the eight need floats as well.
#    4  align-content: safe end — `safe` alignment has no expression in this store's Align enum.
#                          `safe` is an overflow FALLBACK rather than a position, so there is
#                          nowhere to record it, and the fixture is named `_overflow`.
#    4  float            — doc 43's 84 float fixtures, plus these four. See the remarks on
