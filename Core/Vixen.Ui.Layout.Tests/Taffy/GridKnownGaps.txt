# Grid fixtures in Taffy's corpus that Vixen does not yet get right.
#
# Same rules as KnownGaps.txt and BlockKnownGaps.txt beside it, and the same reason for existing: a
# name here is a fixture that LAYS OUT and disagrees with Chrome, which is a different thing from
# the fixtures TaffyStyleMap or TaffyTrackListParser refuse for a property this store has no field
# for. A refusal is a skip and is counted separately; only a numeric disagreement belongs here.
#
# Names are given without the __{border,content}_box_{ltr,rtl} suffix, so one line covers up to four
# fixtures. Group them under a `# ── … ──` heading that says WHY the bucket fails and what would fix
# it — a bare list of names is a changelog, not an explanation, and the shape of this file is
# supposed to be readable as the answer to "what is missing from grid".
#
# TaffyGridConformanceTests asserts both that every failure is listed here AND that the totals are
# exactly the committed counts, so a line cannot quietly widen and a fix cannot quietly land. The
# corollary is the one rule that matters: a gap that closes comes off this file in the same commit
# as it closes, and a gap that opens does not get added without a heading explaining it.
#
# 1526 of the 2 120 grid, blockgrid and gridflex fixtures pass, 462 fail and 132 are refused.
#
# ⚠ THE SHAPE OF THIS FILE IS THE RESULT, and it is a different shape from block's. Block landed
# with every one of its 42 failures outside block formatting. Grid has not: the buckets below are
# real grid gaps, and the two largest — baseline alignment and CSS Grid §9's containing block — are
# whole features rather than arithmetic slips. What IS complete is placement (§8) and the bulk of
# track sizing (§12): every `grid_placement_*`, `grid_auto_flow_*`, `grid_repeat_*`, `grid_gap_*`,
# `grid_span_*` non-indefinite and `grid_relayout_*` family is green, and so are 472 of the 548
# `grid_flex_track_*` fixtures, which are the ones that exercise §12.5 and §12.7 hardest.

# ── BASELINE ALIGNMENT IS NOT IMPLEMENTED (§11.8) ──
#
# `align-items: baseline` on a grid container aligns items by the baseline of their first line box,
# which means shimming each item's intrinsic contribution by the distance from its own baseline to
# its start edge BEFORE §12 sizes the rows — §12.5 step 1 says so in as many words. This store has a
# baseline function and the flex path uses it; grid does not call it at all, so a baseline-aligned
# item is placed as though it said `start`.
#
# 64 of the corpus's 80 `align-items` occurrences are `baseline`, so this is the single largest

# ── AN ABSOLUTELY POSITIONED CHILD'S CONTAINING BLOCK IS NOT ITS GRID AREA (§9) ──
#
# CSS Grid §9 makes the grid area the containing block of an out-of-flow child whose placement is
# definite, which has two consequences: the child's STATIC POSITION is the area's start corner, and
# its INSETS resolve against the area's size. Neither is implemented; an abspos grid child measures
# from the container's padding box, which is what `LayoutTree.Absolute` does for a flex parent.
#
# ⚠ <b>The cheap half was implemented, measured, and taken back out.</b> Recording the area's start
# corner as a static position — reusing the BlockStaticLeft/BlockStaticTop pair block layout already
# has, and letting the absolute walk read it for a grid parent too — is about forty lines and it
# fixed six fixtures in the `_gaps_` and `_container_` families while breaking eight in
# `_align_self_`: a net loss of two against the oracle. The half that pays is the other one, and it
# needs a per-child containing block inside `LayoutTree.Absolute` — a file shared with Yoga's 534
# fixtures and with every flex and block absolute case, so it wants its own commit and its own
# conformance run rather than a grid-shaped patch. Doing the cheap half alone is worse than doing
# neither, and that is a measurement rather than an opinion.
