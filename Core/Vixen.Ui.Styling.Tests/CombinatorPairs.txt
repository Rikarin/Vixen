# Every `A > B` the committed stylesheets declare between two bare type selectors.
#
#     <parent> > <child>  <sheet>
#
# Held against the measured set by
# `CombinatorPairTests.Every_child_combinator_pair_is_in_the_committed_census`, EXACTLY and in both
# directions. Derived: re-run that test with VIXEN_REGENERATE=1 to write this back, and read the diff.
#
# ⚠ This is the DOMAIN and not a verdict. Nothing here says a pairing is live. A rule whose parent
# and child are both real tags that never meet fires on nothing, silently, and both known instances
# were found by a person reading a sheet — `compositor-editor > node-canvas` was one, and the
# compositor's graph was drawn at zero width for as long as it stood. See `Rikarin/Vixen#531`.
#
# ⚠ Why a committed set rather than a count: four audits of this same question reported 88, 72, 75
# and 70 pairs, from four hand-rolled parsers over the same seventeen sheets. A count agrees with all
# four. A set agrees with one, and it is read out of the compiled selector table rather than off the
# sheet's text — so `:is()`, `:not()` and a compound carrying classes beside its tag are decided by
# the compiler and not by a regular expression.
#
# ⚠ A row arriving here is a claim worth one minute of somebody's attention: that an element with the
# parent tag can hold a child with the child tag. Markup nesting proves 14 of these (3 without the
# type->tag map); the other 74 have parents built in C#, most of them a control assembling its own
# parts, which no markup scan can reach.
#
# Child combinators only. A descendant pairing is a weaker claim and was not what the four
# measurements above were of.
