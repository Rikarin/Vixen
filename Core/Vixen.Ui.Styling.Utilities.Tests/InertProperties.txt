# The expiring allow-list for UtilityConsumptionGateTests.
#
# One line per CSS property that a utility family emits and that nothing in the engine acts on yet:
#
#     <css-property>  #<task>  <why, and what closing it looks like>
#
# The task number must be one docs/plan/43-web-styling-parity.md names, or the build fails. A line
# whose property the engine has since learned to read also fails the build — that is the expiry, and
# it is why this is not docs/DocsExempt.txt. So does a line for a property no family emits any more.
# See InertAllowList.cs for the rest of the argument.
#
# Do not add a line here to make a build pass. Adding one is a statement that the engine owes this
# property, and the number is where the debt is recorded. Every line below is a class somebody can
# write today that resolves, computes a value, and changes nothing at all.

# ── Transforms — A7. The four custom properties the transform families park a value in, waiting for
# a transform stage that decomposes and animates one. Nothing reads a `--`-prefixed name at all.
--rotate                     #23  translate/scale/rotate need a real `transform`, decomposed
--scale                      #23  ditto
--translate-x                #23  ditto
--translate-y                #23  ditto

# ── Filters — A8. Same shape one family over: `blur-2` writes a number into a name nothing reads.
--blur                       #28  `filter`/`backdrop-filter` in the UI renderer, blur first

# ── Borders — A1. The physical four are painted now; the two logical edges are not, so `border-s-*`
# and `border-e-*` still colour nothing. The widths *are* read, which is why only the colours are here
# and why this is the shape of partial support the gate can express: one longhand of a family passes
# and its neighbour does not.
border-inline-end-color      #21  per-edge colours reached the draw list; the logical pair did not
border-inline-start-color    #21  ditto

# ── Backgrounds — A11. Closed. `background-image` is parsed into `BoxStyle` and painted, so its line
# is gone and the seven `--tw-gradient-*` fragments are accounted for through it.
#
# `via-*`, stop positions, `bg-radial` and `bg-conic` are painted too now, and the two round assemblers
# emit `background-image` like the eight linear ones — so they add no property here and needed no
# weakening of the gate to land.
#
# ⚠ What remains owed inside A11 still cannot be written here, for the reason it never could: this file
# is keyed by property, and an explicit radial centre or a `background-repeat` that is read for some
# values and not others lives *inside* `background-image`. A line kept for it would fail the expiry
# check the moment the property became read, which it already is. Partial support inside one property
# is the one shape this gate cannot express; the remainder is tracked as A11 in
# docs/plan/43-web-styling-parity.md and refused loudly at runtime rather than approximated — see
# `GradientRefusal`.

# ── Paint the renderer has no channel for — A6.
fill                         #24  `fill`/`stroke` on the OnDraw paths, with `DrawContext`
stroke                       #24  ditto
outline-color                #24  `ring-*` is v3's reading; under v4 it should emit a box-shadow (D5)
user-select                  #24  no selection model reads it, so `select-none` is a promise

# ── Grid — B2. CLOSED. `grid-column` and `grid-template-columns` were here until the bridge landed;
# both are read now, and the `gridded` scene in UtilityConsumptionProbe is what observes them. Note
# what it took to retire these two honestly: the emissions were also wrong — `grid-cols-3` used to
# emit `grid-template-columns: 3`, which is not a track list — so the family would have gone on
# doing nothing even with a reader, and the gate could not have told anyone, because with no grid in
# any scene it measured inert either way. Two of the three failures were invisible to it.
#
# Still absent, and no longer for want of a reader: `grid-rows-*`, `row-span-*`, `col-start-*`,
# `col-end-*`, `row-start-*`, `row-end-*`, `auto-cols-*`, `auto-rows-*`, `grid-flow-*`. The bridge
# reads every one of those properties; the families are simply not registered yet.

# ── Inline formatting — B3. CLOSED for `vertical-align`, and the closing is worth reading.
#
# The line above said "`vertical-align` needs line boxes to align to", which was true and was not
# the whole story — the same shape of half-truth the grid block below records. It named the missing
# algorithm correctly and could not have told anybody when the algorithm arrived, because no scene
# in `UtilityConsumptionProbe` contained a line box: every one of the nine made `#probe` a flex,
# block or grid container, and CSS applies `vertical-align` to none of those. So the property would
# have gone on measuring inert after B3 landed, and this file would have gone on claiming a gap that
# had closed. The `inlined` scene is what gives the gate eyes for it, and it was added in the same
# commit as the algorithm rather than after it.
#
# ⚠ Three of the eight values are implemented and five are not, and the five are NOT a gap in this
# file's sense: `middle`, `text-top`, `text-bottom`, `sub` and `super` are defined against the
# parent's font strut, `Vixen.Ui.Layout` has no font, and `LayoutStyleBuilder` therefore drops them
# rather than mapping them. The property is read; those values are refused at the bridge. The
# utilities that emit them stay inert in `UtilityFamilySupportTests`, which is where a *family*
# rather than a property is recorded. See `InlineKnownGaps.txt`.

# ── Transitions — A20, and this group is the one the survey got wrong. The Animator is finished and
# tested and nothing ever constructs one, so a declared transition has never run. See F10.
transition-duration          #46  nothing builds an Animator; the cascade jumps straight to the value
transition-property          #46  ditto
transition-timing-function   #46  ditto
