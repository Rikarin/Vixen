# The expiring allow-list for UtilityConsumptionGateTests.
#
# One line per CSS property that a utility family emits and that nothing in the engine acts on yet:
#
#     <css-property>  #<task>  <why, and what closing it looks like>
#
# The task number must be one docs/plan/43-web-styling-parity.md names, or the build fails. A line
# whose property the engine has since learned to read also fails the build — that is the expiry, and
# it is why this is not docs/DocsExempt.txt. So does a line for a property no family emits any more.
# See InertAllowList.cs for the rest of the argument.
#
# Do not add a line here to make a build pass. Adding one is a statement that the engine owes this
# property, and the number is where the debt is recorded. Every line below is a class somebody can
# write today that resolves, computes a value, and changes nothing at all.

# ── Transforms — A7. HALF CLOSED, and the half that closed took the other half's name with it.
#
# What was here was four lines: `--rotate`, `--scale`, `--translate-x`, `--translate-y`. Every one of
# them was a debt recorded against a property that does not exist. `--scale` is not CSS; no engine
# anywhere reads it; a family emitting it could not have been fixed by a reader, because there was
# nothing to read. That is exactly the `grid-cols-3` failure — an emission no engine could consume,
# with the debt filed under the wrong name and the gate unable to say so, because a property nothing
# emits and a property nothing reads look identical from here.
#
# `translate` is read now. `UiDocument.Accumulate` resolves it into the same sum that already carried
# `OffsetX`, so the draw list and the hit test see one translated position rather than two opinions of
# it — see `Vixen.Ui.Tests.TransformTests`. `translate-x-*` and `translate-y-*` are composed: a
# `--tw-translate-x`/`--tw-translate-y` fragment each and one `translate` between them, which is what
# lets the two classes coexist instead of the later rule silently zeroing the other axis. The two
# fragments are accounted for through the assembler and carry no lines, like the gradient stops.
#
# The two below are the genuine remainder, and they are now filed under the properties CSS has.
#
# ⚠ Neither is a missing reader, which is the thing worth knowing before somebody "closes" them the
# cheap way. `DrawCommand` is an axis-aligned rectangle and the clip stack intersects rectangles, so:
#
#   `rotate` cannot be represented at all. A rotated box is not a rectangle, and a rotated *clip* is
#   not one either — the per-axis overflow trick of pushing one pair of edges to `UnboundedClip`
#   works precisely because the result is still axis-aligned. Approximating a rotation by its
#   bounding box would make `rotate-45` draw a 45-point square where a 32-point one was asked for,
#   which reads as a rendering bug rather than as a missing feature. Refused, like `GradientRefusal`.
#
#   `scale` is representable as a box and not as a *picture*. Scaling the rectangle is four
#   multiplications; scaling what is in it is not. Glyph advances are shaped at `run.Size` during
#   layout and `DrawCommand.FontSize` carries the size they were shaped at, so a scaled subtree needs
#   re-shaping — which would make a transform affect layout, the one thing CSS Transforms 1 §3 says it
#   must never do. Border widths, radii and shadow offsets are the same story one field at a time.
#   Scaling the box alone gives a box of the right size holding text of the wrong one.
#
# Closing either needs the renderer to composite a transformed subtree — an offscreen target and a
# matrix, which is the same compositor `DrawListBuilder`'s opacity remark already says is owed.
rotate                       #23  a rotated box is not a rectangle, and neither is its clip
scale                        #23  the box scales in four multiplications; the glyphs in it do not

# ── Filters — A8. CLOSED for blur, and it was the same shape as the transforms above: `blur-2` wrote
# a number into `--blur`, a name of this engine's own invention that no assembler and no engine — this
# one or a browser — was ever going to look at.
#
# `filter: blur()` is read now. `blur-*` sets a `--tw-blur` fragment and assembles it into a real
# `filter` declaration; `DrawListBuilder` opens a composited group for it, `UiGeometryBuilder` outsets
# the group's bounds by three sigma, and both executors convolve the finished surface — the device
# with two passes and a shared scratch target, `SoftwareUiRasterizer` with the same kernel from the
# same method. See `Vixen.Ui.Controls.Tests.FilterBlurTests` for the shape and
# `Vixen.Graphics.Golden.Tests.UiCompositingTests` for the two paths agreeing. The fragment carries no
# line here, like the gradient stops and the two translations.
#
# ⚠ What is *not* closed and is deliberately absent from this list: the rest of `filter`, and
# `backdrop-filter`. Neither has a family emitting anything, so neither is a debt this file can
# record — a property nothing emits is exactly the mistake the `--blur` line was. `brightness-*`,
# `contrast-*` and the rest are absent roots in docs/plan/43's ledger, which is where an absence
# belongs; `backdrop-filter` needs the frame *under* a group, which the compositor does not keep.

# ── Borders — A1. The physical four are painted now; the two logical edges are not, so `border-s-*`
# and `border-e-*` still colour nothing. The widths *are* read, which is why only the colours are here
# and why this is the shape of partial support the gate can express: one longhand of a family passes
# and its neighbour does not.
border-inline-end-color      #21  per-edge colours reached the draw list; the logical pair did not
border-inline-start-color    #21  ditto

# ── Backgrounds — A11. Closed. `background-image` is parsed into `BoxStyle` and painted, so its line
# is gone and the seven `--tw-gradient-*` fragments are accounted for through it.
#
# `via-*`, stop positions, `bg-radial` and `bg-conic` are painted too now, and the two round assemblers
# emit `background-image` like the eight linear ones — so they add no property here and needed no
# weakening of the gate to land.
#
# ⚠ What remains owed inside A11 still cannot be written here, for the reason it never could: this file
# is keyed by property, and an explicit radial centre or a `background-repeat` that is read for some
# values and not others lives *inside* `background-image`. A line kept for it would fail the expiry
# check the moment the property became read, which it already is. Partial support inside one property
# is the one shape this gate cannot express; the remainder is tracked as A11 in
# docs/plan/43-web-styling-parity.md and refused loudly at runtime rather than approximated — see
# `GradientRefusal`.

# ── Paint the renderer has no channel for — A6. MOSTLY CLOSED, and the three that closed did so in
# three different ways — which is the argument for reading these lines rather than counting them.
#
# `fill` and `stroke` were the straightforward pair: the emission was already right — v4 emits
# `fill: <color>` and `stroke: <color>` and so did this — and the renderer turned out to have had the
# channel all along. `IconPath` carries a fill paint and a stroke paint, `DrawContext` has
# `FillField` and `Stroke`, and `IconPaintKind.Foreground` is already SVG's `currentColor` marker. So
# closing it was one property read per slot in `Icon.Resolve`, plus the two names in
# `InheritedProperties` without which the class only works when written on the icon itself. Note what
# is *not* closed and is not a missing reader either: `IconPaintKind.Literal` is left alone on
# purpose, because `StandardIcons`' file-type glyphs are brand-coloured deliberately; and there is no
# `stroke-width` family, so CSS cannot summon a stroke onto art that declared none.
#
# `outline-color` is gone entirely, and it is the fourth instance of the failure this file keeps
# finding — after `grid-template-columns: 3`, `--scale`/`--rotate`, and `grid-column: 2`. `ring-*`
# emitted `outline-color`, and **no version of Tailwind has ever emitted that property for this
# family**. The plan's § D5 calls it "v3's reading", which is wrong too: v3 is where the ring was
# introduced *as a box-shadow*, and v3's `ring-<color>` set `--tw-ring-color`. So this was a debt
# recorded against a property nothing anywhere would ever have read — a reader for `outline-color`
# would have closed the line and changed nothing a person could see. The family emits v4's shape now,
# `box-shadow: 0 0 0 <width> <color>`, which `DrawListBuilder.EmitShadow` has painted since it
# learned about spread: a spread grows the rectangle and every corner radius, so a ring is a rounded
# box outside the border box, painted behind it, invisible to layout. No `outline` property, no
# fourth border edge, and no new draw path. What it did need was `currentcolor`, so that a bare
# `ring-2` is the text colour instead of some default nobody chose — see `UtilityComposition.Ring`.
#
# ⚠ The remaining line is the one that is *not* waiting for a reader, and the reason it stays is
# worth more than the line. A selection model does exist — `TextField` has `CaretIndex`,
# `SelectionAnchor`, `SelectWord`, drag-to-select and a highlight it draws in its own `OnDraw`, and
# `CodeEditor` has its own — so the old wording here, "no selection model", was disprovable in five
# minutes and invited exactly the cheap close it was meant to prevent. What is absent is the
# *document-wide* selection CSS is talking about. Both models are per-control: each captures the
# pointer for the duration of its own drag, gates its highlight on focus, and hit-tests only its own
# `TextLayout`. Nothing can drag a selection across a `TextBlock`, a label or two sibling elements,
# and `select-none` on a button — the overwhelmingly commonest way the class is written, to stop a
# double-click selecting the caption — has nothing to suppress because nothing would have selected.
# Teaching `TextField.Pointed` to refuse a drag under `user-select: none` would make this line expire
# while leaving that promise unkept, which is why it was not done.
user-select                  #24  selection is per-control; the document-wide model `user-select` governs does not exist

# ── Grid — B2. CLOSED. `grid-column` and `grid-template-columns` were here until the bridge landed;
# both are read now, and the `gridded` scene in UtilityConsumptionProbe is what observes them. Note
# what it took to retire these two honestly: the emissions were also wrong — `grid-cols-3` used to
# emit `grid-template-columns: 3`, which is not a track list — so the family would have gone on
# doing nothing even with a reader, and the gate could not have told anyone, because with no grid in
# any scene it measured inert either way. Two of the three failures were invisible to it.
#
# Still absent, and no longer for want of a reader: `grid-rows-*`, `row-span-*`, `col-start-*`,
# `col-end-*`, `row-start-*`, `row-end-*`, `auto-cols-*`, `auto-rows-*`, `grid-flow-*`. The bridge
# reads every one of those properties; the families are simply not registered yet.

# ── Inline formatting — B3. CLOSED for `vertical-align`, and the closing is worth reading.
#
# The line above said "`vertical-align` needs line boxes to align to", which was true and was not
# the whole story — the same shape of half-truth the grid block below records. It named the missing
# algorithm correctly and could not have told anybody when the algorithm arrived, because no scene
# in `UtilityConsumptionProbe` contained a line box: every one of the nine made `#probe` a flex,
# block or grid container, and CSS applies `vertical-align` to none of those. So the property would
# have gone on measuring inert after B3 landed, and this file would have gone on claiming a gap that
# had closed. The `inlined` scene is what gives the gate eyes for it, and it was added in the same
# commit as the algorithm rather than after it.
#
# ⚠ Three of the eight values are implemented and five are not, and the five are NOT a gap in this
# file's sense: `middle`, `text-top`, `text-bottom`, `sub` and `super` are defined against the
# parent's font strut, `Vixen.Ui.Layout` has no font, and `LayoutStyleBuilder` therefore drops them
# rather than mapping them. The property is read; those values are refused at the bridge. The
# utilities that emit them stay inert in `UtilityFamilySupportTests`, which is where a *family*
# rather than a property is recorded. See `InlineKnownGaps.txt`.

# ── Transitions — CLOSED by A20 / task #46. All three lines are gone, and the group is worth keeping
# a note for because of how it got here and how it left.
#
# It arrived as the survey's clearest mistake: doc 43 listed two of these as working on the strength
# of the cascade computing a value for them, and `UtilityFamilySupportTests` carried all three in
# `Supported` for the same reason — in the file whose own opening paragraph warns against exactly
# that reading. `Animator` was finished, had three test files of its own, and was constructed nowhere
# but in them, so a document that declared `transition: all 200ms` and then changed a class jumped.
# The gate's first run moved the three rows down here.
#
# ⚠ Closing it took a scene as well as an engine, and that is the third time. A20 wired the animator
# to the style engine and the frame loop, and two of these three properties immediately measured as
# consumers — `transition-property` did not, and would have gone on not doing so for a reason nothing
# in this file could have told you: `transition-duration` defaults to zero, so the property alone
# moves nothing in a plain scene, and the `animated` scene already declared the family's only emitted
# value. The `primed` scene is what gives the gate somewhere to see it. Same lesson as `gridded` and
# `inlined`, arriving for the third time in this file: a green gate is a claim about the scenes as
# much as about the engine.
#
# ⚠ What is *not* closed, and is a family gap rather than a property gap, so it is recorded in
# `UtilityFamilySupportTests` and not here: the `transition` utility emits `transition-property` and
# nothing else, where Tailwind's emits a 150 ms duration and a timing function alongside it. So
# `class="transition"` on its own still does nothing at all and needs a `duration-*` beside it. The
# property is read; the class is half of one.
