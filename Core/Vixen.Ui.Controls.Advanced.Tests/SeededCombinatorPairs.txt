#
# ⚠ These are PROOFS, on `LiveCombinatorPairs.txt`'s terms and with one extra rule that is the whole
# reason the file can be believed: A SEED MAY PUT A CONTROL INTO A STATE AND MAY NEVER BE THE PARENT
# OF THE PAIRING IT PROVES. `A > B` is "provable" for any pair by nesting a `B` under an `A`, so
# every seed reports the elements it introduced by name and the walk refuses those as children. What
# is recorded is the control's RESPONSE — `Tabs.Adopt` building a `tab-panel` under the `tab-panels`
# part when a tab joins the strip, where the seed only ever added the tab. The refusal is asserted
# by name in `The_seeded_sweep_actually_ran`, so a walk that stopped honouring it fails loudly
# instead of quietly growing this file.
#
# ⚠ Only what the bare sweep did NOT already see. A pairing both sweeps reach is the stronger claim
# and lives in `LiveCombinatorPairs.txt`; a copy here would leave the two files disagreeing about
# which one owns the row on the day a control starts building a part earlier.
#
# ⚠ A pairing missing from this file is UNJUDGED and never dead — the seeds are twelve states out of
# every state a control has, and this assembly still cannot see a single editor tag.
# `Core/Vixen.Ui.Styling.Tests/CombinatorPairs.txt` is the domain, `LiveCombinatorPairs.txt` is what
# a bare control builds, and `SuspectCombinatorPairs.txt` is the only file here that makes a
# negative claim.
#
# ⚠ A DEPARTED row has a second reading the bare census does not have: either the control stopped
# building the part — which is the `compositor-editor > node-canvas` defect this question exists for
# — or the SEED stopped putting it in the state that builds it. Read the seed as well as the control.
